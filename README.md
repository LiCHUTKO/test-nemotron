# AETHER // Global Operations Nexus

**REAL-TIME INTELLIGENCE FOR AUTONOMOUS INFRASTRUCTURE**

A cinematic, futuristic enterprise command platform for monitoring distributed
infrastructure, data centers, AI agents, networks, deployments, incidents,
cybersecurity activity and live telemetry — all simulated locally, no backend
required.

## Project overview

AETHER presents a single operator surface across ten mission modules:

- **Overview** — executive global status: 8 live KPIs, backbone throughput,
  platform health and an autonomous-operations feed.
- **Telemetry** — seven golden-signal charts (CPU, memory, throughput,
  bandwidth, latency, errors, IOPS) with 1H / 6H / 24H / 7D ranges and live ticks.
- **Infrastructure** — interactive SVG service topology with health states,
  animated traffic pulses and a resource inspector.
- **Global Map** — stylized dotted-world mesh across 8 regions with animated
  traffic flows and per-region drilldown.
- **Incidents** — command center with severity / status / text filters,
  response timelines and recommended actions.
- **Deployments** — release pipeline with animated phase tracking and live
  progress.
- **AI Agents** — 8-agent autonomous fleet with tasks, confidence, activity logs.
- **Security** — SOC view: threat level, stats and a live sensor event stream.
- **Operations Log** — pausable, filterable live event stream.
- **Terminal** — a real interactive operator console with history and secrets.

Everything runs locally. All data is generated by a centralized deterministic
simulation engine — no API keys, no cloud, no paid services.

## Architecture

Modular feature-based layout with strict separation of concerns:

- `src/app/` — composition root (`App.tsx`), section registry.
- `src/components/` — `layout/` (shell, sidebar, topbar, boot, atmosphere),
  `ui/` (design-system primitives), `visualization/` (charts),
  `palette/`, `notifications/`, `inspector/`.
- `src/features/` — one folder per mission module, lazy-loaded via
  `React.lazy` for code splitting.
- `src/lib/` — pure logic: `simulation` (seeded RNG + random-walk series),
  `terminal` (command interpreter), `filters` (incident search), `chart`,
  `format`.
- `src/hooks/` — single-owner intervals only (`useLiveSeries`, `useKpis`,
  `useClock`, `useEventSimulation`, `useKonami`); every timer is cleaned up.
- `src/data/` — convincing static operational datasets.
- `src/stores/` — Zustand global store (section, environment, compact/motion
  modes, inspector selection, toasts).
- `src/styles/` — token system (`tokens.css`) + layout / component / feature
  layers.
- `src/types/` — shared domain models.

Key decisions:

- **Centralized simulation** — one seeded engine (`mulberry32` + mean-reverting
  random walk) instead of scattered `setInterval` randomness, so charts look
  like real signals and tests are deterministic.
- **Pure, tested cores** — terminal parsing, incident filtering and series
  math are side-effect-free modules covered by Vitest.
- **Progressive disclosure** — heavy views are code-split; the shell boots
  through a short staged sequence into an animated workspace.
- **Accessibility & motion** — semantic landmarks, focus states, ARIA labels,
  and full `prefers-reduced-motion` support wired into every animation.

## Installation

Requirements: **Node.js 18.18+** (CI uses Node 22).

```bash
git clone https://github.com/LiCHUTKO/test-nemotron.git
cd test-nemotron
npm ci
```
